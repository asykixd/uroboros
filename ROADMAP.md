# Roadmap

План развития Uroboros до 1.0 и после. Версии примерные: порядок важнее номеров.
Отмеченное `[x]` уже сделано.

## Принципы

- **Ядро маленькое, всё остальное — модули.** Встроенные команды пишутся на том же публичном API, что и сторонние.
- **API похож на Hikka.** Адаптер совместимости должен остаться тонким слоем, а не вторым ядром.
- **Обычный Telethon 1.x.** Форк, как Hikka-TL, не делаем. На Telethon 2 переходим только после его стабильного релиза.
- **Работает везде, где есть Python 3.10+:** VPS/Linux, Termux, Windows, macOS. Новая зависимость должна ставиться в Termux без компиляции.
- **Только русский язык.**
- Ветка разработки — `master`. Релизы помечаются тегами `vX.Y.Z` (беты — `vX.Y.ZbN`).

## 0.2 — Расширенный API модулей

Цель: модули умеют всё, что обычно нужно, без обращения к внутренностям ядра.

- [x] `@loop(interval, autostart=True)` — фоновые задачи, автоматически останавливаются при выгрузке
- [x] Автоочистка: обработчики, которые модуль повесил через `self.client.add_event_handler`, снимаются при выгрузке
- [x] Шорткаты `self.get(key, default)` / `self.set(key, value)`
- [x] Фильтры команд: `only_pm`, `only_groups`, `chats=[...]`, `no_reply` и т.п.
- [x] Метаданные в шапке модуля: `# meta developer:`, `# meta version:`, `# requires_uroboros: 0.2`. Если версия ядра не подходит, модуль не грузится и пользователь получает понятное сообщение
- [x] Библиотеки: общий код для нескольких модулей (`self.import_lib(url)`) с подсчётом ссылок
- [x] `strings` с подстановкой (`self.strings("key", **kw)`), HTML-экранирование по умолчанию
- [x] Хелперы в `utils`: `get_user`, `get_target`, `get_chat_id`, `get_reply`, `run_sync`, `answer_file`
- [x] Хук `on_dlmod` — однократная настройка при первой установке модуля
- [x] Документация по API в `docs/` и примеры модулей в `examples/`

## 0.3 — Inline-бот

Цель: интерактивные формы и кнопки, как в Hikka.

- [ ] Бот на aiogram 3 в том же процессе, что и юзербот
- [ ] Автосоздание бота через @BotFather при первом запуске; токен можно задать и вручную
- [ ] Включение inline-режима и выдача кнопок через BotFather автоматически
- [ ] `self.inline.form(message, text, buttons)` — сообщение с кнопками вместо своего исходящего
- [ ] `self.inline.list` (страницы), `self.inline.gallery` (картинки)
- [ ] Кнопки с колбэками, вводом текста и подтверждением; колбэки снимаются при выгрузке модуля
- [ ] Декораторы `@inline_handler` и `@callback_handler`
- [ ] Inline-версии встроенных команд: `.cfg` с кнопками, `.help` со страницами, подтверждение `.ulm`
- [ ] Проверить, что aiogram 3 (pydantic v2, `pydantic-core` на Rust) ставится в Termux. Если нет — искать замену или делать inline-бот необязательным extra

## 0.4 — Доступ и безопасность

Цель: аккаунтом можно делиться командами, и его сложнее случайно сломать.

- [ ] Владелец и группы доступа: `owner`, `sudo`, `support`
- [ ] Права на команду (`.security <команда> <группа>`), права по умолчанию задаются в `@command`
- [ ] Команды от других пользователей (входящие сообщения) — только при явной выдаче прав
- [ ] `.e`, `.t`, `.dlm` и `.ulm` по умолчанию доступны только владельцу
- [ ] Защита от флуда API: считать запросы и замораживать модули, которые шлют их слишком часто
- [ ] Перед установкой из неподключённого источника показывать, откуда модуль и сколько в нём строк, и просить подтверждение (кнопкой из 0.3)
- [ ] Предупреждать, если модуль обращается к файлам сессии, `config.json` или `os.environ`. Это эвристика, а не песочница

### Безопасность модулей

Строгая, но без песочницы: защита от опасного и чужого кода, а не от любого Python.

- [ ] Проверка исходника при установке, обновлении (`.uplm`) и восстановлении (`.restore`): опасное блокируется, пока пользователь явно не подтвердит (`-f`), подозрительное показывается в ответе
- [ ] `# requires:` принимает только имена пакетов с версиями, без ссылок и опций pip
- [ ] Модули скачиваются только по https
- [ ] Защита во время работы: сторонние модули не получают доступ к сессии, файлам в `data/` и запросам, которые угрожают аккаунту

## 0.5 — Веб-панель первого входа

Цель: установить юзербот без консольного диалога, в том числе на VPS и в Termux.

- [ ] aiohttp-сервер, который поднимается только когда нет сессии
- [ ] Шаги: api_id/api_hash → номер → код → пароль 2FA; вход по QR-коду
- [ ] Одноразовый токен в ссылке; по умолчанию слушает `127.0.0.1`
- [ ] Доступ с VPS через SSH-проброс или туннель, с инструкцией
- [ ] Консольный вход остаётся как запасной (`--cli`)
- [ ] После входа сервер выключается: панель не висит постоянно

## 0.6 — Адаптер модулей Hikka

Цель: большинство популярных модулей Hikka/FTG работают без правок.

- [ ] Распознавать модули Hikka: `from .. import loader, utils`, `from hikkatl`, `@loader.tds`
- [ ] Шимы в `sys.modules`: `hikkatl` → `telethon`, `loader`, `utils`, `..inline.types`
- [ ] `loader.Module`, `loader.command`, `loader.watcher`, `loader.loop`, `loader.tds`, суффикс `xxxcmd`, `client_ready(client, db)`
- [ ] `loader.ModuleConfig` / `ConfigValue` / `validators` в формате Hikka
- [ ] `strings` / `strings_ru`, `self.get` / `self.set`, `self.allmodules`, `self.lookup`
- [ ] `utils.*` Hikka: `answer`, `get_args*`, `escape_html`, `get_user`, `run_sync`, `get_link`, …
- [ ] `self.inline.form` и `@loader.inline_handler` поверх inline-бота из 0.3
- [ ] Декораторы прав Hikka (`@loader.owner`, `@loader.sudo`) поверх системы доступа из 0.4
- [ ] Набор проверки совместимости: автоматически загрузить N популярных модулей из hikariatama/ftg и других репозиториев и вести таблицу, что работает
- [ ] Список того, что не поддерживается (возможности Hikka-TL, внутренности Hikka), с понятной ошибкой при загрузке

## 0.7 — Установка и эксплуатация

Цель: поставить и обновлять бота одной командой.

- [ ] `install.sh` для Linux и Termux: зависимости, venv, первый запуск
- [ ] systemd-unit (user service) для VPS; автозапуск в Termux через Termux:Boot
- [ ] Docker-образ и `docker-compose.yml`, данные в volume
- [ ] Инструкции для Windows и macOS
- [ ] Каналы обновлений `stable` / `beta`; `.update` показывает changelog перед установкой
- [ ] Уведомление о новой версии (раз в сутки, отключается)
- [ ] Автобэкап БД в приватный чат или «Избранное» по расписанию

## 1.0 — Стабильный релиз

Цель: публичный API, на который можно опираться.

- [ ] API модулей заморожен: semver, политика устаревания (deprecation-предупреждения минимум на одну минорную версию)
- [ ] Полная документация для разработчиков модулей (сайт на mkdocs или GitHub Pages)
- [ ] Официальный репозиторий модулей `uroboros-modules` и шаблон репозитория для авторов
- [ ] Поиск модулей по подключённым репозиториям (`.search`)
- [ ] Публикация на PyPI (`pip install uroboros`)
- [ ] Покрытие тестами загрузчика, диспетчера, адаптера и inline-слоя
